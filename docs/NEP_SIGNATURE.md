# Система усиленной неквалифицированной электронной подписи (НЭП)

## Описание

Система НЭП реализована в соответствии с требованиями:
- **ФЗ-63** "Об электронной подписи"
- **ст. 22.3 ТК РФ** для внутреннего документооборота

Система использует:
- **RSA-2048** для криптографического преобразования
- **SHA-256** для хеширования
- **PKCS#7** (CMS) для формата подписи
- **Отсоединенные подписи** (.p7s файлы)

**Важно:** Система НЕ требует:
- Удостоверяющего центра (УЦ)
- Корневых сертификатов
- CryptoPro или других коммерческих СКЗИ

## Архитектура

### Компоненты системы

1. **SQL миграция** (`postgresql/migrations/26__nep_signature.sql`)
   - `employee_keys` - хранение ключевых пар сотрудников
   - `document_signatures` - метаданные подписей

2. **Python модуль** (`python_service/nep_signer/`)
   - `signer.py` - класс NEPSigner для подписания/проверки
   - `sign_handler.py` - API хендлер для подписания
   - `verify_handler.py` - API хендлер для проверки

3. **C++ хендлеры**
   - `/v1/employee/keys/generate` - генерация ключевой пары
   - `/v1/documents/nep-sign` - подписание документа
   - `/v1/documents/nep-verify` - проверка подписи

## API Endpoints

### 1. Генерация ключевой пары

**POST** `/v1/employee/keys/generate`

Генерирует RSA-2048 ключевую пару для текущего пользователя.

**Headers:**
```
Authorization: Bearer <token>
```

**Response 200:**
```json
{
  "employee_id": "uuid",
  "public_key": "-----BEGIN PUBLIC KEY-----\n...",
  "public_key_hash": "sha256_hash",
  "created_ts": "2026-01-31T12:00:00"
}
```

**Response 400:**
```json
{
  "message": "Ключи для этого сотрудника уже существуют"
}
```

### 2. Подписание документа

**POST** `/v1/documents/nep-sign?document_id=<uuid>`

Подписывает PDF документ с использованием НЭП.

**Headers:**
```
Authorization: Bearer <token>
Content-Type: application/json
```

**Request Body (опционально):**
```json
{
  "reason": "Согласование",
  "location": "Москва"
}
```

**Response 200:**
```json
{
  "signature_id": "uuid",
  "signature_path": "document_id.p7s",
  "timestamp": "2026-01-31T12:00:00",
  "public_key_hash": "sha256_hash"
}
```

**Response 400:**
```json
{
  "message": "Ключи электронной подписи не найдены"
}
```

**Response 404:**
```json
{
  "message": "Документ не найден"
}
```

### 3. Проверка подписи

**GET** `/v1/documents/nep-verify?signature_id=<uuid>`

Проверяет действительность электронной подписи документа.

**Headers:**
```
Authorization: Bearer <token>
```

**Response 200:**
```json
{
  "valid": true,
  "integrity_ok": true,
  "signature_ok": true,
  "message": "Подпись действительна",
  "verified_at": "2026-01-31T12:05:00",
  "signer_name": "Иванов Иван Иванович",
  "signature_timestamp": "2026-01-31T12:00:00"
}
```

**Response 404:**
```json
{
  "message": "Подпись не найдена"
}
```

## Workflow использования

### Первоначальная настройка

1. **Генерация ключей** (выполняется один раз для каждого сотрудника):
   ```bash
   curl -X POST https://api.example.com/v1/employee/keys/generate \
     -H "Authorization: Bearer <token>"
   ```

### Подписание документа

2. **Подписание документа**:
   ```bash
   curl -X POST "https://api.example.com/v1/documents/nep-sign?document_id=<uuid>" \
     -H "Authorization: Bearer <token>" \
     -H "Content-Type: application/json" \
     -d '{
       "reason": "Согласование документа",
       "location": "Москва, офис"
     }'
   ```

3. **Проверка подписи**:
   ```bash
   curl -X GET "https://api.example.com/v1/documents/nep-verify?signature_id=<uuid>" \
     -H "Authorization: Bearer <token>"
   ```

## Безопасность

### Хранение ключей

- **Приватные ключи** хранятся в базе данных в зашифрованном виде (требуется настройка шифрования БД)
- **Публичные ключи** доступны для проверки подписей
- **Хеши публичных ключей** используются для быстрой идентификации

### Рекомендации

1. **Включить шифрование на уровне БД** для таблицы `employee_keys`
2. **Настроить резервное копирование** ключей
3. **Ограничить доступ** к таблице `employee_keys` на уровне СУБД
4. **Логировать** все операции с ключами и подписями

## Проверка целостности

Система проверяет:

1. **Целостность документа** (`integrity_ok`)
   - Документ не был изменен после подписания
   - Хеш документа совпадает с хешем в подписи

2. **Криптографическую корректность** (`signature_ok`)
   - Подпись создана с использованием приватного ключа
   - Проверка проходит с использованием соответствующего публичного ключа

3. **Общая действительность** (`valid`)
   - `valid = integrity_ok AND signature_ok`

## Юридическая значимость

### Соответствие законодательству

Система соответствует требованиям:

- **ФЗ-63 ст. 5 п. 2** - усиленная неквалифицированная электронная подпись
- **ТК РФ ст. 22.3** - использование электронного документооборота

### Ограничения

НЭП подходит для:
- ✅ Внутреннего документооборота
- ✅ Согласования документов внутри компании
- ✅ Подтверждения ознакомления с документами

НЭП НЕ подходит для:
- ❌ Взаимодействия с государственными органами
- ❌ Банковских операций
- ❌ Сделок с юридической значимостью за пределами организации

Для таких случаев требуется **квалифицированная электронная подпись (КЭП)**.

## Устранение неполадок

### Ошибка "Ключи не найдены"

**Причина:** Ключи не сгенерированы для сотрудника

**Решение:**
```bash
curl -X POST https://api.example.com/v1/employee/keys/generate \
  -H "Authorization: Bearer <token>"
```

### Ошибка "Подпись недействительна"

**Возможные причины:**
1. Документ был изменен после подписания
2. Подпись повреждена
3. Используется неверный публичный ключ

**Решение:**
- Проверить целостность документа
- Пересоздать подпись

### Ошибка "Document was corrupted"

**Причина:** PDF файл поврежден или модифицирован

**Решение:**
- Восстановить оригинальный документ
- Пересоздать подпись
